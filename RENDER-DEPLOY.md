## ✅ Why Render Works

This app uses **SQLite** (file database) and **local file uploads** (product photos, logo, QR code).
Both need a **persistent filesystem** — which serverless platforms (Vercel, Netlify) do NOT have.

Render provides **persistent disks** (like Railway), so the app works with **zero code changes**.

| Feature | Vercel / Netlify | **Render** |
|---|---|---|
| SQLite database | ❌ Read-only filesystem | ✅ Persistent disk |
| Local file uploads | ❌ Lost on every deploy | ✅ Persisted in disk |
| Code changes needed | Major rewrite (Postgres + cloud) | **ZERO** |
| Persistent disk | ❌ Not available | ✅ $0.25/GB/month |

Render should auto-detect the `render.yaml` Blueprint in your repo and pre-fill most settings.

If it doesn't auto-detect, set these manually:

| Setting | Value |
|---|---|
| **Name** | `bike-shop-os` (or any name you like) |
| **Runtime** | **Docker** |

## Step 3: Verify Environment Variables

These should be auto-set from `render.yaml`. Verify they're present:

| Variable | Value | Auto-generated? |
|---|---|---|
| `DATABASE_URL` | `file:/data/custom.db` | ✅ From render.yaml |
| `SESSION_SECRET` | (random string) | ✅ Auto-generated by Render |
| `NODE_ENV` | `production` | ✅ From render.yaml |
| `STORAGE_DIR` | `/data` | ✅ From render.yaml |

### Optional: Enable AI Features

The app works fully without AI. To enable the AI assistant, image recognition,
voice search, and smart insights, add these as environment variables:

| Variable | Value |
|---|---|
| `ZAI_API_KEY` | Your Z.AI API key (from https://z.ai) |
| `ZAI_BASE_URL` | `https://api.z.ai/v1` |

> When these are set, the app auto-creates its config file. When not set,
> AI endpoints return a friendly error and the rest of the app works normally.

## Step 4: Verify the Persistent Disk

The `render.yaml` Blueprint automatically creates a disk. Verify:

| Disk Setting | Value |
|---|---|
| **Name** | `data` |
| **Mount Path** | `/data` |
| **Size** | `1 GB` |

> This `/data` disk is where:
> - SQLite DB lives: `/data/custom.db`
> - Product photos: `/data/uploads/products/`
> - Shop logo: `/data/uploads/logos/`
> - UPI QR code: `/data/uploads/qr/`
>
> Everything persists across deploys and restarts.

## Step 5: Deploy!

1. Click **"Create Web Service"** (or "Apply Changes")
2. Render starts building — this takes **3-8 minutes** on first deploy
3. Watch the build logs — you'll see:
   - `bun install` (installing dependencies)
   - `next build` (building the Next.js app)
   - Docker image creation
4. Once deployed, the startup command runs automatically:
   - `prisma db push` (creates database tables)
   - `bun run prisma/seed.ts` (injects initial data)
   - `node server.js` (starts the server)

## 🆘 Troubleshooting

### Build fails
- Check **"Logs"** tab → read the build error
- Common: missing `Dockerfile` → make sure it's committed to GitHub
- Common: repo not connected → re-authorize GitHub App

### App loads but shows error / can't login
- Check logs for seed errors
- The DB might not have initialized → open Render Shell and run:
  ```bash
  bun run prisma/seed.ts
  ```

### Images don't upload / don't display
- Disk not attached → verify in Settings → Disks (must be at `/data`)
- Check `STORAGE_DIR=/data` is set in environment variables

### Data disappears between deploys
- Disk not attached, or wrong mount path → must be `/data`
- Did you choose "Free" plan? Free doesn't have disks → switch to Starter

### "Port" errors
- The Dockerfile sets `PORT=3000`, but Render sets its own `PORT` env var
- The Next.js standalone server auto-reads `process.env.PORT`
- If issues, check logs for the actual port the server is using

### AI features don't work
- `ZAI_API_KEY` not set → add it in Environment (optional — core app works without AI)
